## Tooling investment with measured benefit

Concurrent long agent advances exposed the global session lock blocking unrelated phone requests. Each session now has its own simulation lock; collection access remains protected, same-session commands serialize, and the real-time clock skips a busy world instead of waiting on it.

Beneficiaries: owner playing while an agent tests another village, and independent reviewers running isolated scenarios. Cost: a localized locking change and a focused concurrency probe, with the maintenance obligation to keep each world single-writer. This is not a generic orchestration framework or a promise of unlimited concurrency.

In three dense-village advance probes, unrelated heartbeat responses were1975/2081/2133ms before and12/10/11ms after, while advances still took1608–3491ms. Concurrent commands on the same village preserved exactly30seconds of combined advancement. Different builds/test villages and ordinary host load limit the benchmark; the explicit lock separation plus observed latency reduction establish the removed cross-session block. CPU/storage contention can still occur.
