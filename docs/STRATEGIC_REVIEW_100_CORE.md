# Strategic correction after100 — complexity before confidence

Triggered by the user's September27 question: have we accumulated complexity without knowing the core mechanics are right? This is the immediate independent strategic review required by AGENTS, not checkpoint101. Game remains fixed `97f9b7f`; prior documents `d80eda3`. No new implementation, play, listening or tests. Five separate existing reviewer contexts reused their100 evidence independently: design100, UX100, play100, lead100 and visual90/100. No role saw the other new responses before returning. This is an evidence-based reassessment, not five new playtests.

## Verdict and responsibility

Yes: implementation breadth exceeds confidence in the experience. The project proves physical work, meals, geometry and revisions more strongly than a desire to play. The core is promising, not proven wrong: a small inhabited farmstead, useful ground, understandable travel and forgiving arrangement have a coherent purpose. More features cannot supply the missing preference evidence.

The implementation/review process contributed. Repeated reviews found the next worthwhile decision unproven, then approved more ways to inspect or change the village. A scripted revision cannot establish that a player wants to revise. The lead shares responsibility; this is not a deficiency caused by the user's first game project. Checkpoint counts are bookkeeping, not product validation.

## Independent conclusions

- **Design:** stop automatic batching. Keep physical consequences and limited useful land; household management, overlapping venues and processing breadth have not earned expansion. Test choosing homes/livelihood, observing use and a wanted improvement or satisfying ending. Nearby small workplaces may dominate everything; reject the core if that exhausts its pleasure.
- **UX:** the101–105 queue is still overbuilding despite conditional labels. It commits conceptual space to scenario, interface, landscape and scheduling before uncoached evidence. Reduce first-use prominence of exchange/manual staffing/advanced systems; retain full catalogue access. Fix actual interference, not every hypothetical discoverability concern. Visual appeal is part of the core, not automatically optional polish.
- **Playtest evidence audit:** test a small set of homes, cultivation, timber, shared work and meals/rest. Preserve the fuller build as control. Scripted ordinary-control success proves a route exists, not that someone wants it. The review process must permit rejection of the core instead of another defending feature batch.
- **Development lead:** a satisfying short session counts. Use current architecture and tools; no rewrite or generalized configuration framework. Human interpretation is now the bottleneck. One unfamiliar-player session can reveal a worthwhile next decision, misunderstanding or satisfied ending; it is directional evidence, not a statistical verdict.
- **Visual/audio:** the current low houses and cultivation suffice for this test. Prioritize meaningful entrances, destinations, worked ground and actual use over roof variants/props/counters. A full landscape redesign earns priority if arranging is pleasurable but the result feels visually generic. Reused100 images, no new play/listening.

## Synthesis, disagreements and selected test

Replace101–105 with **one comparison and a decision**. First observe the existing frozen build with an unfamiliar player, ideally the user, for roughly15–25 minutes maximum or until they choose to finish. Invitation: make a small place you would like these neighbors to live in. No coordinates, build order, required improvement or duration target. Explain basic controls when needed; record any assistance instead of calling it unaided.

Observe reasons for placement, understanding of consequences, recovery, voluntary changes/watching and contented finishing. Ask afterward which moment they would keep and what they wanted to do next. Controls understood but no cared-for result or wanted action challenges the core. A clear desire obstructed by a specific control justifies fixing that obstruction. Short satisfied play is success; lengthy waiting is not proof of depth.

If breadth interferes, compare a reduced first-use surface with the same simulation and current full version as control: homes, cultivation, a modest timber supply, actual work/meals/rest, reversible placement, pause/speed and one inspect/follow/back flow. Keep Normal/relaxed as comparisons, not additional content work. Existing inhabited state can isolate improvement from founding; no new map required initially.

Play/visual favor hiding the full catalogue for the experiment; design/UX retain access under the user's brief. Decision: reduce default prominence while preserving full catalogue access, no building locks. Some roles propose a wanted revision as a test requirement; lead/design correctly allow contented finishing. Decision: no compulsory revision. Some want two livelihoods immediately; start from the current build and narrow only where observed, rather than building a new balanced alternative in advance.

Preserve code/Git and deferred systems. No wholesale deletion, compatibility work or architecture rewrite. Household exchange, industrial chains, overlapping services and broad management stay secondary, not new test goals. Do not require artwork to become worse to prove mechanics: current useful presentation remains. Equally, do not commission a landscape overhaul before checking whether that addresses the player's actual reaction.
